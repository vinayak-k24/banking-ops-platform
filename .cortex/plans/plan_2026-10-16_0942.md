## Implementation steps
**Backend**
1. **Dependencies (need your OK):**
   - `pypdf` and `python-docx` to extract text.
   - `python-multipart`, which FastAPI needs for file uploads.
   - `fpdf2` to export the plan as PDF.
   - Embeddings use `google-genai`, which comes with ADK, so no new package.
2. **`services/document_storage.py`:** saves the raw upload to GCS when `gcs_bucket` is set, otherwise to a local `backend/uploads/` folder (gitignored).
   - Limits: 50 MB per file and 1500 pages.
   - Accepted types: pdf, docx, md and txt.
3. **`services/vector_index.py`:**
   - Splits text into chunks of about 1,000 tokens with overlap, keeping the page number for each chunk.
   - Embeds chunks with `text-embedding-004` when agents are enabled. Otherwise it uses a deterministic hashed bag-of-words vector, so tests and offline demos still work.
   - Stores chunks in a new `migration_chunks` collection through `get_store()` and searches them by cosine similarity. Embeddings are sent in batches so 1000-page documents work.
4. **`tools/migration_planning.py`:** the deterministic core.
   - `build_inventory`: validates the extracted components against a Pydantic schema. Each component has a name, a type (database, data, stored procedure/query, application code, batch job, integration, infrastructure), a size, a complexity and its dependencies.
   - `order_phases`: sorts components so dependencies always come first, and within that follows a fixed type order: infrastructure → database schema → data → queries/procedures → application code → integrations/batch jobs → cutover. It fails if dependencies form a loop.
   - `estimate_effort`: effort = size × complexity factor × risk buffer, using `Decimal`. Gives person-weeks per phase and an overall timeline based on team size, with phases running in sequence or in parallel where dependencies allow.
5. **`workflows/migration_planning.py`:** the workflow, registered in `registry.py`. Steps:
   1. Extract the text.
   2. Chunk and embed it.
   3. Search the document for each topic: systems, databases, code, dependencies, integrations, non-functional requirements and risks.
   4. Gemini extracts the components as structured JSON, citing pages. Without Gemini, a keyword-based extractor does this instead.
   5. Order the components and estimate effort (deterministic).
   6. Gemini writes the narrative: rationale, risks and rollback for each phase.
   7. Verification checks:
      - every component is assigned to a phase;
      - no dependency rule is broken;
      - the timeline adds up;
      - every phase has supporting citations.
      If any check fails, the task does not reach SUCCEEDED.
   8. Render the report.
   Large documents run as background tasks, and the existing task polling shows progress.
6. **`services/migration_report.py`:** Markdown is the main output (fastest, and the IDE agent can read it back). PDF is rendered from the same content. It includes the executive summary, an ordered phase table, a Gantt-style timeline table, dependencies, risks and assumptions.
7. **Variation 2 (IDE agent):** `GET /api/migration/codebase-prompt` returns a prompt the user pastes into their VS Code or other IDE agent.
   - The prompt asks the agent to produce `MIGRATION_CONTEXT.md` with fixed headings: overview, languages/frameworks, modules, databases/schemas, queries/procedures, dependencies, integrations, build/deploy, tests, and known issues.
   - The file also starts with a YAML block that lists the components in machine-readable form.
   - When this file is uploaded with `source_type=codebase_summary`, the YAML is validated and used directly, so no LLM extraction step and more deterministic results. If the YAML is invalid, it falls back to the document path.
8. **API `api/migration.py`:**
   - `POST /api/migration/documents` (multipart upload with `source_type`, `target_platform` and `team_size`) creates the task.
   - `GET /api/migration/plans/{task_id}` returns the plan.
   - `GET /api/migration/plans/{task_id}/report?format=md|pdf` downloads the report.
   - Every action writes an audit event. Request models are added to `schemas.py`.
9. **Migration agent:** add tools to `migration_agent` (`search_migration_document` and `get_migration_plan`) so the Gemini drawer can answer questions about an uploaded plan.
