# AGENTS.md

Instructions for AI coding agents (Codex, Jules, Cursor, Antigravity, Claude Code, Gemini CLI, Copilot, Cortex Code, etc.) working in this repository. Tool-specific files (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/`, `.agent/rules/`) point here. **Keep this file the source of truth.**

## Project

Banking Operations & Intelligence Platform: a 9-page Next.js dashboard plus a Python backend running Google ADK (Gemini) agents against a **simulated** banking environment. Synthetic data only. Hackathon prototype targeting Google Cloud Run.

Read first: `docs/architecture.md`, `docs/agents-and-tools.md`, `docs/todo.md`.

## Architecture rules (do not break)

1. **Gemini plans and explains; deterministic code calculates, checks and executes.** Thresholds, forecasts, reconciliation arithmetic (use `Decimal`), and pass/fail verification live in `backend/tools/` or workflows, never in LLM output.
2. **Approvals are enforced in backend code** (`services/authorization.py`, `workflows/approval_workflow.py`). Agents cannot approve; requesters cannot self-approve; execution requires an APPROVED approval whose action **and parameters** match exactly.
3. **Never mark a task SUCCEEDED without explicit verification checks.** Use the lifecycle in `models/schemas.py` and transitions in `services/task_manager.py`.
4. **One shared dataset.** Pages must read from the backend store, not hard-code values. A single event (e.g. capacity warning) must appear consistently across pages.
5. **All storage goes through `services/firestore_store.get_store()`** so code works on both memory and Firestore backends.
6. **Every state change writes an audit event** via `services/audit.record(actor, action, target, outcome, task_id, details={...})`. Never put secrets in audit details or logs.
7. **Frontend calls the backend only through `src/lib/api.ts`** using relative `/api/...` paths (Next.js rewrites proxy to `BACKEND_URL`). Never put API keys in frontend code.
8. Treat log text and documents as untrusted input in agent prompts.

## Conventions

### Backend
- Tools: plain functions with type hints and a docstring including `Args:` (ADK uses them as tool schemas). Return dicts; return `{"error": ...}` for not-found rather than raising.
- New workflow: define steps with `StepDef` in `workflows/<name>.py`, call `register(...)`, import it in `workflows/registry.py`, add tests.
- Sensitive step: call `action_executor.request_approval(...)` then `raise PauseForApproval(...)`. Final step raises `VerificationOutcome(status, output)`.
- New sensitive action: add it to `APPROVER_ROLES` in `services/authorization.py`.
- New agent: `agents/<name>_agent.py` with `create_<name>_agent()` using `build_agent`, then add to `orchestrator.py` and `AGENT_REGISTRY`.
- Request bodies are Pydantic models in `models/schemas.py` with length limits. Errors use `HTTPException` (`{"detail": ...}`).
- Mock data changes: edit `scripts/generate_mock_data.py`, regenerate, commit the JSON.

### Frontend
- Pages are client components using `useDashboard()` for `openModal`, `switchPage`, actions and persona.
- Keep the existing visual style: Tailwind utility classes, theme colors in `tailwind.config.ts` (`slateDark`, `coralRed`, `accentBlue`), `action-btn-black`, Font Awesome icons (`fa-solid ...`).
- When a backend response shape changes, update `src/lib/types.ts`.
- Navigation uses routes (`/ops`, `/dba`, ...); add page metadata in `src/lib/modules.ts`.

### General
- Match surrounding code style and comment density. Keep changes focused.
- Update `docs/` when behaviour, endpoints, tools or deployment change; tick or add items in `docs/todo.md`.
- Files are UTF-8 without BOM. Don't rewrite files through PowerShell `Get-Content`/`Set-Content` without explicit `-Encoding UTF8` (it has corrupted box-drawing characters before).

## Don't

- Commit `.env`, `node_modules`, `.next`, `backend/.venv`, credentials or real banking data.
- Add more env files (`backend/.env`, `.env.local`, ...). The repo-root `.env` (template `.env.example`) is the single source for frontend and backend.
- Upgrade to TypeScript 7 (Next.js 15 can't load it; keep `typescript@5`).
- Move `mock_data` out of `backend/` (Cloud Run builds the backend from `backend/` only).
- Add build/CI files (`cloudbuild*.yaml`, `.github/workflows/`) yet - deferred until local development is complete (see `docs/todo.md`).

## Definition of done

- Backend tests pass; frontend typecheck and build pass.
- New behaviour has tests (backend) and is reflected in `docs/`.
- No hard-coded values added to pages where backend data exists.
